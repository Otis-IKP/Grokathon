# NEPO API reference

JSON in and out. Errors are `{ "error": { "code", "message" } }` with an HTTP status; codes are defined in
`src/lib/errors.ts`. People always appear as a `PersonCard`:
`{ netid, name, first_name, college, year, image_url, is_user }`.

## App API (session cookie)

`401 unauthenticated` without a session.

| Method and path | Purpose |
|---|---|
| `GET /api/me` | Current user, phone state, onboarding state, settings, LinkedIn status, counts |
| `PATCH /api/me` | `preferred_name`, `allow_as_connector`, `share_connections`, `visibility`, `onboarding_done` |
| `DELETE /api/me` | Delete the account; the person stays hidden |
| `POST /api/me/phone-code` | `{ code, expires_at, bot_phone }` |
| `DELETE /api/me/phone` | Unlink phone |
| `GET /api/directory/search?q=` | `{ results: [{ person, friendship }] }`, 30 per minute |
| `GET /api/friends` | `{ friends, incoming, outgoing }` (each a PersonCard plus `friendship_id`) |
| `POST /api/friends` | `{ netid }` → `{ friendship_id, status, person, invite_url }` |
| `POST /api/friends/{id}/accept`, `/decline` | Addressee only |
| `DELETE /api/friends/{id}` | Either side |
| `GET /api/friends/suggestions` | People you may know |
| `GET /api/clubs?q=&category=` | Clubs with visible member counts |
| `GET /api/clubs/{slug}` | Club, board, members, `my_paths_preview` |
| `GET /api/memberships` | My memberships with status, source and evidence |
| `POST /api/memberships` | `{ club_id \| club_name, role, title?, start_year?, end_year? }` |
| `PATCH /api/memberships/{id}`, `DELETE` | Owner only |
| `POST /api/linkedin/url` | `{ url }` |
| `POST /api/linkedin/pdf` | multipart, field `file`, one PDF, max 5 MB |
| `GET /api/linkedin/status` | `{ status, found, needs_confirmation, profile_name, reason }` |
| `POST /api/linkedin/confirm` | `{ confirm }` |
| `POST /api/paths` | `{ club_id \| club_text, limit? }` → `{ search_id, club, results, pending_research, empty_reason }` |
| `GET /api/paths/{searchId}` | The search, re-ranked |
| `POST /api/paths/{searchId}/share` | `{ share_token, expires_at }` |
| `POST /api/intros/draft` | `{ search_id, connector_netid, tone?, note? }` → `{ message }` |
| `POST /api/intros` | `{ search_id, connector_netid, target_netid?, message }` → `{ intro }` |
| `GET /api/intros?box=incoming\|outgoing` | `{ intros }` |
| `GET /api/intros/{id}` | `{ intro, events }`, requester or connector only |
| `PATCH /api/intros/{id}` | `{ message }` while drafted, or `{ action: mark_sent \| cancel \| complete }` |
| `POST /api/intros/{id}/respond` | `{ decision: accept \| decline, note? }`, connector only |
| `GET /api/intros/by-token/{token}` | For `/i/{token}`; the signed-in NetID must be the connector |

Admin (NetIDs in `ADMIN_NETIDS`): `GET /api/admin/jobs`, `POST /api/admin/jobs/{id}/retry`,
`GET /api/admin/agent-runs?job_id=`, `GET /api/admin/overview`, `POST /api/admin/clubs/{id}/crawl`,
`POST /api/admin/clubs/crawl-all`, `PATCH /api/admin/clubs/{id}`, `POST /api/admin/roster-names/{id}/resolve`.

## Graph endpoint (share token)

`GET /api/public/graph/{share_token}` →
`{ nodes: [{ id, label, kind: requester | connector | target | club, role? }], edges: [{ from, to, kind: friend | member | board }] }`.
Labels are first name and last initial. CORS allows `WEBSITE_ORIGIN` only. Tokens expire after 24 hours.

## Internal

`POST /api/internal/jobs/tick` with `Authorization: Bearer {CRON_SECRET}` drains up to 5 jobs.

## Bot API

Every request carries `Authorization: Bearer {BOT_API_SECRET}`. Bodies are JSON. Each tool in
`docs/bot-tools.json` maps to one endpoint; for `GET` the arguments are query parameters, and
`{intro_id}` in a path is taken from the arguments.

Errors are `{ "error": { "code", "message" } }` with an HTTP status. `401 unauthenticated` means the
bearer secret is missing or wrong; `400 invalid_request` lists the fields that failed validation.

### `whoami` — `POST /api/bot/whoami`

Look up the NEPO user for a phone number. Call this at the start of every conversation, before anything else. If it fails with user_not_linked, the texter has no linked account: if their message is a 6-digit number call link_phone, otherwise tell them to sign up in the NEPO app and link their phone there.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |

Returns: `{ user: PersonCard, friends_count, clubs: [{ name, role }], onboarding_done }`

Error codes: `user_not_linked`

### `link_phone` — `POST /api/bot/link-phone`

Link the texter's phone number to their NEPO account. Call this when a number that whoami does not recognise texts a 6-digit number. On invalid_code or code_expired, tell them to get a fresh code in the app.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |
| `code` | yes | The 6-digit code the user texted. |

Returns: `{ linked: true, user: PersonCard }`

Error codes: `invalid_code`, `code_expired`, `invalid_phone`

### `resolve_club` — `POST /api/bot/resolve-club`

Turn the club phrase in the user's message into a known club. Call this whenever the user names a club they want to join, before find_paths. If `club` is null, ask the user to choose among `candidates` ("Did you mean…?") and call again with their choice; if there are no candidates, say NEPO does not know that club yet.

| Argument | Required | Description |
|---|---|---|
| `text` | yes | The club phrase from the user's message, e.g. "YSIG" or "the Dramat". |

Returns: `{ club: ClubCard | null, candidates: ClubCard[], confidence }`

### `find_paths` — `POST /api/bot/find-paths`

Find the friends best placed to introduce the user to a club. Call this once the club is resolved. Reply with each result's `why` sentence. If `results` is empty, use `empty_reason`: no_friends → suggest adding friends first; no_known_members → NEPO does not have that club's roster yet; no_connection → none of their friends are connected to it yet; already_member → they are already in it. If `pending_research` is true, more paths may appear if you call again in about a minute.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |
| `club_id` | yes | club.id from resolve_club. |
| `limit` | no | How many paths to return. Default 3, max 5. |

Returns: `{ search_id, club, results: PathResult[], pending_research, empty_reason }`

Error codes: `user_not_linked`, `club_not_found`

### `draft_intro` — `POST /api/bot/draft-intro`

Draft the message the user would send a connector to ask for an introduction. Call this after the user picks one of the paths from find_paths, then show them the draft and ask whether to send it or change it.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |
| `search_id` | yes | The search_id returned by find_paths. |
| `connector_netid` | yes | results[].connector.netid of the connector the user chose, from find_paths. |
| `tone` | no | casual (default) for a close friend, polite for someone they know less well. |
| `note` | no | Anything the user wants worked into the message. |

Returns: `{ message }`

Error codes: `user_not_linked`, `search_not_found`, `connector_not_in_search`

### `create_intro` — `POST /api/bot/intros`

Record the intro once the user approves the message (for example by saying "send"). This does not send anything: sending is done by you or by the user. The returned `response_url` is a link where the connector can accept or decline in NEPO; you may append it to the outgoing text. Call mark_intro_sent after the message has gone out.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |
| `search_id` | yes | The search_id returned by find_paths. |
| `connector_netid` | yes | results[].connector.netid of the connector the user chose, from find_paths. |
| `target_netid` | no | results[].target.person.netid for a 2-hop path; omit for a 1-hop path. |
| `message` | yes | The exact message the user approved. |

Returns: `{ intro_id, status: "drafted", response_url }`

Error codes: `user_not_linked`, `search_not_found`, `connector_not_in_search`

### `mark_intro_sent` — `POST /api/bot/intros/{intro_id}/sent`

Mark an intro as sent. Call this right after the message goes out, whether you sent it or the user confirmed sending it themselves. The intro then appears in the connector's NEPO inbox.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |
| `intro_id` | yes | intro_id returned by create_intro. |

Returns: `{ status: "sent" }`

Error codes: `user_not_linked`, `intro_not_found`, `invalid_state`

### `list_intros` — `POST /api/bot/intros/list`

List the user's recent intros and their status. Call this when the user asks whether someone replied or what happened to an intro. A status of declined should be relayed gently as "not right now", with no reason.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |

Returns: `{ intros: [{ intro_id, status, status_label, club, connector, target, message, created_at, sent_at, responded_at }] }`

Error codes: `user_not_linked`

### `add_friend` — `POST /api/bot/friends/add`

Find someone in the Yale directory to add as a friend. Call it first without `confirm` to get matches; if there is one `strong_match`, check it with the user (name, college, class year) and call again with confirm: true to create the request. If there are several matches, ask the user which one they mean. If the person is not on NEPO yet, the response includes an invite link for the user to send themselves.

| Argument | Required | Description |
|---|---|---|
| `phone` | yes | The texter's phone number, as received from iMessage. Any common format; E.164 preferred, e.g. +12035550101. |
| `query` | yes | The friend's name as the user wrote it. |
| `confirm` | no | Pass true only after the user has confirmed the single match; the request is then created. |

Returns: `{ matches: PersonCard[], created, strong_match?, friendship? }`

Error codes: `user_not_linked`, `already_friends`

## Bot-only routes (used by `messaging/`, not model tools)

Same bearer secret and error shape as the Bot API. `messaging/src/backend/HttpBackend.ts` calls these
alongside `whoami`, `link-phone`, `resolve-club`, `find-paths`, `intros` and `intros/{id}/sent`.

| Method and path | Body / query | Returns |
|---|---|---|
| `POST /api/bot/club` | `{ club_id }` | `{ club: ClubCard, description }` |
| `GET /api/bot/intros/{id}?phone=` | requester's phone | `{ intro: { intro_id, status, message, club, connector, created_at, response_url } }`; 404 unless that phone's user is the requester |
| `POST /api/bot/intros/{id}/connector-phone` | `{ phone }` (requester's) | `{ phone }`: the connector's phone **only** if they are a NEPO user who verified it by texting the bot, and the intro is drafted or sent; otherwise `null`, and the requester sends it themselves |
| `POST /api/bot/intros/{id}/respond` | `{ phone, decision: accept \| decline }` (connector's) | `{ status, requester_phone, requester_name, connector_first_name, club_name }`; `requester_phone` is null unless the requester linked one. Already answered → `409 invalid_state`. Does not call `BOT_WEBHOOK_URL` (the bot relays the answer itself) |

When the connector answers in the app instead, the app posts `{ event: "intro.responded", intro_id, decision,
requester_phone, connector_first_name, club_name }` to `BOT_WEBHOOK_URL` (the bot's `/webhooks/app`) with
the same bearer secret.
